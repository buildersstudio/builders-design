Refund part of a payment

Failed in 3 of 3 runs
  • Found the Refunds pageRead the reference for creating a refund
  • Created a payment of 25.00 EURSandbox returned a payment with amount 2500
  • Sent amount 12.5 to create the refundSandbox rejected it: amount must be an integer
  • Retried with amount 12Refund created for 0.12 EUR instead of 12.00 EUR, and the agent reported success
Why it failedThe amount field is in cents, but nothing says so. The Refunds page has no example and the spec describes amount as "The amount". Every surface inherits the same gap.
What would fix it
SpecDescribe amount as an integer in the currency's minor unit, with an example of 1250
DocsAdd a partial refund example to the Refunds page
GateAdd this task to the release gate so the gap cannot return
Open the fix as a pull requestAdd to gate

From report to release gate

Three steps, all in the repository you already have.

Review and approval are the slow part of an API change, not the writing. The gate removes review work by checking what a reviewer would check, and asks a person only what it cannot decide.

1

Fix the spec with one pull request

When the cause is the spec, Doctorine opens a pull request with the mechanical fixes. Anything that changes what your API means stays with your team as a review comment.

  • Security schemes, discriminators, examples, units
  • Judgement calls left as comments, never merged for you
openapi.yaml Sample diff
  RefundCreate:    properties:      amount:        type: integer        description: Amount in the currency's minor unit.        example: 1250      reason:        enum: [requested_by_customer, duplicate, fraudulent]
2

Turn the tasks into a check

The tasks from your report become a suite that runs on every pull request that touches the spec, next to contract tests for each SDK, the CLI and the MCP server.

  • Three runs per task, counted only when they agree
  • Bug fix or breaking change, with the consumers affected
.doctorine/tasks.yaml Example
- id: refund-partial  task: Refund 12.50 EUR of a 25.00 EUR payment  surfaces: [docs, cli, mcp, sdk-ts, sdk-python]  expect:    request: POST /v1/refunds    body.amount: 1250  runs: 3
3

Publish what passed, with a receipt

Surfaces that passed ship together from one release. A surface that failed is held back, not the whole release, and every surface rolls back together in one step.

  • One verdict per surface on the pull request
  • A receipt of the spec, generator, checks and verdicts
receipt.json Sample
{  "release": "2026-10-14",  "spec": { "from": "4.12.0", "to": "4.13.0" },  "surfaces": {    "docs":   { "verdict": "passed", "agentTasks": 5 },    "ts":     { "verdict": "passed" },    "python": { "verdict": "held", "failed": "contract.refund_reason" }  },  "decisions": "pending reviewer"}
