Release gate: publiceer alleen de API-interfaces die slaagden

Een check op de pull request die je spec wijzigt. Het bouwt elke interface opnieuw, draait contracttests en je agenttaken, houdt tegen wat faalde en legt vast wat er live ging.

Word designpartner →Bekijk prijzen
Bij elke pull request op de spec

Rood, dan groen. Dan gaat alles samen live.

  • Eén oordeel per interface: docs, CLI, MCP-server, elke SDK en de skill.
  • Een gefaalde interface wordt tegengehouden, met de oorzaak en de fix van één regel.
  • Na de fix draait alleen de geraakte interface opnieuw.
  • Publiceren zet elke geslaagde interface in één keer op de nieuwe release.

Review

Beoordeel twee dingen, geen tweehonderd.

Een agent schrijft een wijziging in seconden. Goedkeuring is waar de weken in gaan zitten. De gate haalt de mechanische review van de lijst en laat je alleen de keuzes die een mens vragen.

Classificatie van de wijziging

Gedeeltelijke terugbetalingen ronden nu half naar boven af op de cent.

Klanten die totalen afstemmen kunnen verschillen van één cent zien. De gate kan niet bepalen of dit voor jouw gebruikers een bugfix of een breaking change is.

Terminologieregel

De nieuwe enum-omschrijving zegt bezorgreden.

Jullie stijlregel zegt verzending, nooit bezorging. Misschien is het bewust. Dat is een keuze voor een mens, dus de gate vraagt het een mens.

Wat je kunt overslaan: 38 formuleringschecks, 212 contracttests en 24 agenttaken slaagden bij deze voorbeeldwijziging. De gate heeft ze beoordeeld.

Bewijs

Elke release laat bewijs achter.

De hash van de spec, de versies van generator en kernel en de hash van elke output, plus de beslissingen die een mens nam. Releases zijn content-geadresseerd en worden via een pointer geactiveerd, dus terugdraaien zet elke interface samen terug.

Deployment

Het zit in je CI, niet in de weg.

De gate draait op de pull request die de spec wijzigt. De Doctorine GitHub App werkt alleen in repositories die jij kiest, met kortlevende tokens per repository, en vraagt nooit om secrets te schrijven of instellingen te wijzigen.

FAQ

Vragen

Waar draait de release gate?

Als check op de pull request die je spec wijzigt, in je eigen repository. Doctorine bouwt elke interface opnieuw vanuit die revisie en geeft één oordeel per interface, naast je andere checks.

Wat gebeurt er als één interface faalt?

Die interface wordt tegengehouden, met de oorzaak en de fix. Elke interface die slaagde, kan nog steeds samen live, en wijst naar dezelfde release.

Vervangt het onze reviewers?

Het vervangt het mechanische deel van de review. Reviewers beslissen nog steeds wat een check niet kan, zoals of een gedragswijziging een fix of een breaking change is, en die beslissing komt in het bewijs.

Wat staat er in het bewijs?

De hash van de spec, de versies van generator en kernel, de hash van elke output en de beslissingen die een mens nam. Een publiek voorbeeld staat op doctorine.xyz/proof/doctorine-sdk-receipt.json.

Kunnen we terugdraaien?

Ja. Releases zijn content-geadresseerde artefacten die via een pointer worden geactiveerd, dus terugdraaien zet elke interface samen terug naar de vorige release.

Hoe krijgen we het?

De release gate is beschikbaar voor designpartners. Een plek kost 100 euro per maand voor een persoon en 300 euro per maand voor een bedrijf, voor drie tot zes maanden.
