Voor publieke API-teams: specwijzigingen die je klanten nog kunnen gebruiken

Je API bedient betalende klanten en partners die versies vastpinnen en op je voorbeelden bouwen. Doctorine toetst elke specwijziging aan de taken die zij echt doen, op elke interface, voordat de wijziging live gaat.

Het probleem

Waar het vandaag breekt

  • Een specwijziging is gemerged, maar tutorials en voorbeelden beschrijven nog de API van vorige maand.
  • Het is lastig om een bugfix van een breaking change te onderscheiden, en voor welke klanten.
  • Goedkeuring gaat langs meerdere reviewers, omdat niemand ziet wat al gecontroleerd is.

FAQ

Vragen

Moeten we ons docsportaal verhuizen?

Nee. De evaluatie en de gate werken op de docs die je vandaag host. Het Doctorine-portaal is een optie, niet het startpunt.

Kan het zeggen of een wijziging breaking is?

De gate bepaalt wat er in de spec veranderde en welke interfaces het raakt. Kan hij niet beslissen of een gedragswijziging een fix of een breaking change is, dan vraagt hij het een mens en legt hij de beslissing vast in het bewijs.
