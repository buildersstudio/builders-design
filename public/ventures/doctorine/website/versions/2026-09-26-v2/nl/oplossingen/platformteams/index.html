Voor platformteams: één check in CI in plaats van nog een reviewlaag

Meerdere teams bewerken één spec, en elke wijziging moet docs, SDK's, de CLI en de MCP-server bereiken zonder een week afstemming. Doctorine draait als check op de pull request, waar je spec al staat.

Vraag een gratis evaluatie aan →Bekijk prijzen
Het probleem

Waar de tijd in gaat

  • Veel teams bewerken dezelfde spec, dus elke wijziging vraagt afstemming voordat ze klaar is.
  • Clients en docs worden in verschillende tools gebouwd, op verschillende versies.
  • Elke nieuwe tool voegt pull requests toe om te reviewen, dus geen enkele blijft hangen.
Classificatie van de wijziging

Gedeeltelijke terugbetalingen ronden nu half naar boven af op de cent.

Klanten die totalen afstemmen kunnen verschillen van één cent zien. De gate kan niet bepalen of dit voor jouw gebruikers een bugfix of een breaking change is.

Terminologieregel

De nieuwe enum-omschrijving zegt bezorgreden.

Jullie stijlregel zegt verzending, nooit bezorging. Misschien is het bewust. Dat is een keuze voor een mens, dus de gate vraagt het een mens.

Wat je kunt overslaan: 38 formuleringschecks, 212 contracttests en 24 agenttaken slaagden bij deze voorbeeldwijziging. De gate heeft ze beoordeeld.

FAQ

Vragen

Welke toegang heeft de GitHub App nodig?

Hij werkt alleen in repositories die jij kiest, met kortlevende tokens per repository. Hij vraagt nooit om secrets te schrijven of repositorybeheer te wijzigen.

Kunnen we het binnen ons eigen netwerk draaien?

Vandaag niet. Zelf hosten is nog niet beschikbaar. Is dat de blokkade, laat het weten, want dat bepaalt wat we hierna bouwen.
