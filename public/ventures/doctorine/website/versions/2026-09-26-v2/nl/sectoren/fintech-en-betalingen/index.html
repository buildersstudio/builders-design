Voor fintech- en betaal-API's: het juiste bedrag, bij elke release

Betaal-API's falen stil en duur: een terugbetaling in de verkeerde munteenheid, een retry die twee keer afschrijft, een webhook die zonder geldige handtekening wordt vertrouwd. Doctorine test die taken met agents voor elke wijziging live gaat.

Het probleem

De fouten die geen foutmelding geven

  • Bedragen in centen die de docs nergens noemen, zodat een agent centen terugbetaalt in plaats van euro's.
  • Idempotency keys die wel in de spec staan maar niet in de gids, zodat een retry twee keer afschrijft.
  • Webhook-handtekeningen over een body die de docs niet beschrijven.

Veilig betalen bij een retry

Mislukt met alleen docs

  1. Vond de pagina PaymentsGeen vermelding van idempotency op de pagina
  2. Maakte een betaling201
  3. Probeerde opnieuw na de gesimuleerde time-outEr werd een tweede betaling aangemaakt
Waarom het misgingDe Idempotency-Key-header staat in de spec maar niet in de docs, dus een agent die alleen de docs leest, rekent twee keer af.

Deel van een betaling terugbetalen

Mislukt met alleen docs

  1. Vond de pagina RefundsLas de referentie voor een terugbetaling
  2. Maakte een betaling van 25,00 EURSandbox gaf amount 2500
  3. Stuurde amount 12.5Geweigerd: amount moet een integer zijn
  4. Probeerde opnieuw met amount 12Betaalde 0,12 EUR terug en meldde succes
Waarom het misgingHet veld amount is in centen, maar dat staat nergens. De spec noemt het alleen het bedrag en de pagina heeft geen voorbeeld, dus elke interface erft het gat.
Wat het oplost
SpecBeschrijf amount als integer in centen, met een voorbeeld van 1250
DocsVoeg een voorbeeld van een gedeeltelijke terugbetaling toe
CheckVoeg deze taak toe aan de release gate zodat het gat niet terugkomt
