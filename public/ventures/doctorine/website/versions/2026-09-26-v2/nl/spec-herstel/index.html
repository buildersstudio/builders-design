Hoe het werkt

Van een spec die niemand vertrouwt naar één reviewbare pull request.

  1. 01ScanDoctorine leest openapi.yaml, of de spec achter je publieke docs, en toetst die aan wat docs, SDK's, de CLI, MCP-tools en agents nodig hebben.
  2. 02Leg uitElk probleem wordt helder beschreven, met de operaties die het raakt en de interfaces die het breekt.
  3. 03Open één pull requestMechanische fixes komen in één pull request die je beoordeelt zoals elke andere. Afwegingen worden reviewopmerkingen bij de regels waar ze over gaan.
  4. 04Houd het opgelostNa de merge controleert de release gate elke volgende wijziging, zodat dezelfde problemen niet terugkomen.
FAQ

Vragen

Wat wijzigt spec-herstel zelf?

Alleen mechanische fixes die niet veranderen wat je API betekent, zoals een ontbrekend security scheme, een discriminator, consistente namen, voorbeelden en gedocumenteerde foutresponses. Al het andere blijft een reviewopmerking.

Merget het iets?

Nee. Het opent één pull request en je team beoordeelt en merget die. Branch protection en verplichte checks blijven gelden.

En als onze spec verre van compleet is?

Dan is spec-herstel het nuttigst. Het rapport laat zien hoe ver de spec af is van wat generatie en agents nodig hebben, en welke fixes het grootste deel van het gat als eerste dichten.
