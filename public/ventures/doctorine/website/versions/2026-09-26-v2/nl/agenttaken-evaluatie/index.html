Agenttaken-evaluatie: kan een agent de klus klaren met je API?

Coding agents proberen de echte integratietaken van je gebruikers, tegen een sandbox op basis van je spec, op elke interface die je publiceert. Het rapport laat zien welke taken slaagden, waar ze faalden en welke wijziging elk probleem oplost.

Hoe het werkt

Vijf taken die je gebruikers in week één doen.

De evaluatie leest alleen wat je publiceert. Geen migratie, geen login en geen productiesleutels nodig.

  1. 01Lees wat je publiceertJe publieke docs, je OpenAPI-spec en wat je uitbrengt aan CLI, MCP-server en SDK's.
  2. 02Schrijf de takenVijf taken uit je eigen operaties en voorbeelden, het werk dat een nieuwe integrator als eerste doet: aanmaken, betalen, terugbetalen, opvragen, verifiëren.
  3. 03Draai ze drie keerTwee coding agents proberen elke taak op elke interface, drie runs per taak, tegen een sandbox die antwoordt vanuit je spec. Een taak telt alleen als alle runs het eens zijn.
  4. 04Rapporteer de fixElke fout komt met de stap waar het misging, de oorzaak in je docs of spec en de kleinste wijziging die het oplost.
Taken, geen scores

Een score zegt dat de bestanden bestaan. Een taak zegt dat het werkt.

Gratis readinesstools controleren of llms.txt, Markdown en sitemaps er zijn. Ze kunnen niet zeggen of een agent een betaling in de juiste munteenheid kan terugbetalen.

FAQ

Vragen

Wat heeft de evaluatie van ons nodig?

Een publieke docs-URL en, als je die publiceert, een link naar je OpenAPI-spec. Toegang tot je repository, je productie-API of inloggegevens is niet nodig.

Welke agents voeren de taken uit?

Twee coding agents voeren elke taak uit op elke interface die je publiceert, drie keer per taak. Het rapport noemt de gebruikte agents en versies, zodat een run te herhalen is.

Hoe blijven de resultaten eerlijk?

Taken komen uit je eigen operaties en voorbeelden, en je ziet ze in het rapport. Een taak telt alleen als geslaagd of mislukt als alle drie de runs het eens zijn. Al het andere heet wisselend en telt niet mee.

Roept het onze productie-API aan?

Nee. Taken draaien tegen een sandbox die antwoordt vanuit je spec, dus er worden geen productiesleutels gebruikt en geen echte data aangeraakt.

Wat is het verschil met de Docs Analyser?

De Docs Analyser op doctorine.dev is een statische check die scoort of agents je docs kunnen vinden en lezen. De evaluatie draait echte taken, dus je ziet of agents ze ook afronden.

Wat kost het?

Het evaluatierapport is gratis. Teams die dezelfde taken bij elke pull request willen laten controleren, stappen over op de release gate.
