For platform teams: one check in CI instead of another review layer

Several teams edit one spec, and every change has to reach docs, SDKs, the CLI and the MCP server without a week of coordination. Doctorine runs as a check on the pull request, where your spec already lives.

The problem

Where the time goes

  • Many teams edit the same spec, so every change needs coordination before it is ready.
  • Clients and docs are rebuilt in different tools, on different versions.
  • Every new tool adds pull requests to review, so none of them sticks.
Change classification

Partial refunds now round half-up to the minor unit.

Clients that reconcile totals may see one cent differences. The gate cannot tell whether this is a bug fix or a breaking change for your users.

Terminology rule

The new enum description says delivery reason.

Your style rule says dispatch, never delivery, for fulfilment. It might be deliberate. That is a call for a person, so the gate asks one.

What you can skip: 38 wording checks, 212 contract tests and 24 agent tasks passed on this sample change. The gate reviewed them.

Where to start

Three steps, the first one free.

  1. 01Install the GitHub AppOn the spec repository only. You choose which repositories it can see.
  2. 02Choose the tasksStart from the eval report and keep the tasks that matter to your users.
  3. 03Turn on the checkIt runs on every spec pull request, next to your other checks.
FAQ

Questions

What access does the GitHub App need?

It works only in the repositories you select, with short-lived single-repository tokens. It never asks to write secrets or change repository administration.

Can we run it inside our own network?

Not today. Self-hosting is not available yet. If it is the blocker, tell us, because it decides what we build next.
