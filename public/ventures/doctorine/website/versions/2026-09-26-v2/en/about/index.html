About Doctorine

We build the check that tells an API team whether agents and developers can still use their API after a change. Doctorine is early software, and says so.

Why we exist

Agents became the main reader of API docs. Nobody checks what they do with them.

On Mintlify-hosted docs, agents went from 15.2% of traffic at the start of 2026 to 66% in July, according to Mintlify's midyear report. Generating a client from a spec now takes an agent seconds. What stays scarce is proof that the docs, SDKs and tools are still correct for this release.

So Doctorine sells proof, not generation: a free report on the docs you have, then a gate in your CI, with generated surfaces as the upgrade.

Source: Mintlify, The state of docs traffic, 2026 midyear report, 29 July 2026. mintlify.com

What we believe

Five rules we build by.

  1. 01Successful use is the outcomeAn API is only as good as the task a developer or an agent can finish with it. That is what we measure.
  2. 02The approved release is the unitDocs, SDKs, CLI, MCP server and skills belong to one release, and move together or not at all.
  3. 03Remove review, never add itA tool that adds pull requests to review will not be used. A check that removes a step will.
  4. 04Start where teams areOn the docs they already host and the spec they already have, without a migration first.
  5. 05Say what is unfinishedDoctorine is early software. We label samples as samples and early access as early access.
