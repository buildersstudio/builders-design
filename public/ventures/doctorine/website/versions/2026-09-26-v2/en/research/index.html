How 33 public API docs portals look to AI agents

On 25 September 2026 we ran the free Doctorine Docs Analyser on 33 public API documentation portals. Sixteen returned a score and seventeen returned an incomplete scan. Most portals are readable. Few are discoverable. None of this says whether an agent finishes a task.

What it means

Four things the numbers say.

Discovery is the weakest category

Among the 16 scored sites, agent and API discovery averaged 40 out of 100, against 83 to 91 for findability, delivery and bot policy. Agents can read most portals, but struggle to find the API and its tools from the docs alone.

Markdown for Agents splits the field

All 9 sites scoring 73 or more passed Markdown for Agents, and all 7 scoring below 70 failed it. It is the clearest single line between the top and the bottom half of this sample.

llms.txt is common, catalogs are not

26 of 33 sites passed the llms.txt check, while 27 had no API Catalog and 27 had no MCP Server Card. The file most people talk about is already there. The ones that point an agent at the API are not.

A score is not a finished task

None of these checks runs an integration. They say whether an agent can find and read the docs, not whether it can create, pay, refund or list. That is what the agent task eval measures. Agent task eval

Method

How we ran it, and what to be careful with.

Each portal was submitted to the analyser's own endpoint at doctorine.dev, the same call the page makes, on 25 September 2026. The response combines the Cloudflare Agent Ready benchmark signals with Doctorine's own probes.

Sites that came back as an incomplete scan were retried up to three more times, 20 to 30 seconds apart. We kept the latest scored run, or otherwise the attempt with the fewest unverified signals. Nothing is estimated: a site without a score is reported without one.

The sample is 33 portals, not a random draw of the market, and 17 scans were incomplete. That may reflect the analyser's probe budget rather than the sites, and it has not been diagnosed. Treat the numbers as a snapshot of one day.

FAQ

Questions

Which portals were included?

Public documentation portals of 33 API companies, 10 in Europe and 23 elsewhere. 25 run on a bespoke platform, 3 on Mintlify, 2 on GitBook, 2 on Docusaurus and 1 on Redocly. We publish aggregates only.

Why did so many scans come back incomplete?

The analyser withholds a score when too many signals cannot be verified. It happened most often when probes for the machine-readable spec and MCP endpoint were limited or unavailable. This may be the analyser's probe budget rather than the sites, and it has not been diagnosed.

Can we check our own portal?

Yes. The same analyser is free at doctorine.dev.
