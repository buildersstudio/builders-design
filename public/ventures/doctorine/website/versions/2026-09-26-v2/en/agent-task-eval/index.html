How it works

Five tasks your users do in week one.

The eval reads only what you publish. It needs no migration, no login and no production keys.

  1. 01Read what you publishYour public docs, your OpenAPI spec and whichever of the CLI, MCP server and SDKs you ship.
  2. 02Write the tasksFive tasks from your own operations and examples, the jobs a new integrator does first: create, pay, refund, list, verify.
  3. 03Run them three timesTwo coding agents attempt each task on each surface, three runs each, against a sandbox that answers from your spec. A task counts only when all runs agree.
  4. 04Report the fixEvery failure comes with the step where it went wrong, the cause in your docs or spec, and the smallest change that fixes it.
Tasks, not scores

A score tells you the files exist. A task tells you it works.

Free readiness tools check whether llms.txt, Markdown and sitemaps are there. They cannot tell you whether an agent can refund a payment in the right currency unit.

FAQ

Questions

What does the eval need from us?

A public docs URL and, if you publish one, a link to your OpenAPI spec. It does not need access to your repository, your production API or any credentials.

Which agents run the tasks?

Two coding agents run every task on every surface you publish, three times each. The report names the agents and versions used, so a run can be reproduced.

How do you keep the results fair?

Tasks are written from your own operations and examples, and you see them in the report. A task counts as passed or failed only when all three runs agree. Anything else is reported as flaky and not counted.

Does it call our production API?

No. Tasks run against a sandbox that answers from your spec, so no production keys are used and no real data is touched.

How is this different from the Docs Analyser?

The Docs Analyser at doctorine.dev is a static check that scores whether agents can find and read your docs. The eval runs real tasks, so it shows whether agents can complete them.

What does it cost?

The eval report is free. Teams that want the same tasks checked on every pull request move to the release gate.
