What is Doctorine

A check that agents and developers can still use your API, on every change.

Doctorine is an API release gate. Before a change ships, it proves that coding agents and developers can still complete real tasks with your docs, CLI, MCP server, SDKs and Agent Skills. It publishes only the surfaces that passed and keeps a receipt of what was checked.

It works on top of the docs you already have. When a surface is missing, Doctorine generates it from your OpenAPI spec and puts it through the same gate.

Starts on the docs you haveThe free eval reads your public docs and spec. No migration, no production keys.
Runs in your CIA check on the pull request that changes the spec, next to your other checks.
Publishes only what passedA failed surface stays behind. Every release leaves a receipt.
The problem

Agents don't fail loudly. They fail politely.

In this sample run, a coding agent read the docs, called the API, refunded 12 cents instead of 12.50 euros and reported success. Nothing crashed, so nobody filed a ticket.

  • A retry charges the customer twice, because the idempotency header is in the spec but not in the docs.
  • A report stops after the first page of results, because no example follows the cursor.
  • A webhook is trusted without a valid signature, because the docs never say what was signed.

A readiness score cannot see any of this. It checks that files exist, not that tasks finish.

A spec change reads fine in review. Then the Python SDK sends the old field name, a tutorial keeps last month's example, and an agent quietly gets a refund wrong.

Writing the change takes an agent seconds. Approving it is where the weeks go. Doctorine takes the mechanical review off the list, so reviewers only decide what a check cannot.

FAQ

What teams ask first

What is Doctorine?

Doctorine is the release gate for APIs. Before an API change ships, it checks that coding agents and developers can still complete real tasks with the docs, CLI, MCP server, SDKs and Agent Skills, publishes only the surfaces that passed and keeps a receipt of what was checked.

Do we have to migrate our docs to use it?

No. The free eval report reads the docs and spec you already publish, wherever they are hosted. The release gate runs in your own repository. The Doctorine portal is an option, not a requirement.

How is this different from an agent readiness score?

A readiness score checks whether files such as llms.txt, Markdown pages and sitemaps exist. The eval runs real integration tasks with coding agents, so it shows whether an agent can actually create, pay, refund or list with your API, and why it fails when it cannot.

Which surfaces does Doctorine check?

The docs portal, the CLI, the MCP server, TypeScript, Python and Go SDKs and Agent Skills. You can check the surfaces you already have, and generate the missing ones from your OpenAPI spec.

What does it cost?

The Docs Analyser and the eval report are free. The release gate is available to design partners at 100 euros a month for an individual and 300 euros a month for a company. Public plans are not published yet.

Where is our data stored?

Core content and tenant stores are configured in EU regions. A small number of services, such as authentication and payments, are documented carve-outs outside the EU.
