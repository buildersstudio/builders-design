For fintech and payments APIs: the right amount, every release

Payment APIs fail in quiet, expensive ways: a refund in the wrong currency unit, a retry that charges twice, a webhook trusted without a valid signature. Doctorine tests those tasks with agents before each change ships.

The problem

The failures that do not throw errors

  • Amounts in minor units that the docs never state, so an agent refunds cents instead of euros.
  • Idempotency keys that exist in the spec but not in the guide, so a retry charges twice.
  • Webhook signatures computed over a body the docs do not describe.

Refund part of a payment

Failed on docs only

  1. Found the Refunds pageRead the reference for creating a refund
  2. Created a payment of 25.00 EURSandbox returned amount 2500
  3. Sent amount 12.5Rejected: amount must be an integer
  4. Retried with amount 12Refunded 0.12 EUR and reported success
Why it failedThe amount field is in minor units, but nothing says so. The spec describes it as the amount and the page has no example, so every surface inherits the gap.
What would fix it
SpecDescribe amount as an integer in minor units, with an example of 1250
DocsAdd a partial refund example to the Refunds page
CheckAdd this task to the release gate so the gap cannot return
