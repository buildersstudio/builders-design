Security and deployment: what Doctorine touches and where it runs

The free eval reads only what you already publish. The release gate runs in your repository with narrow GitHub App permissions. Core data stays in the EU, and every limit is written down.

The free eval

Public docs in, report out.

The eval reads your public docs and, if you publish one, your OpenAPI spec. Tasks run against a sandbox that answers from the spec, so no production keys are used and no real data is touched.

A public, synthetic or redacted definition is enough for a first pass. Do not send credentials or private production data.

The release gate

A GitHub App that works only where you let it.

You choose the repositories. Each operation uses a short-lived, single-repository token instead of a broad installation token.

Each control, with the limit around it.

Residency

EU data at rest for the core data plane

Core content and tenant stores are in EU regions. 11 of 16 declared subprocessor rows are EU-resident; 5 non-EU carve-outs cover services such as authentication, payments and consented analytics. This is not a claim of EU-only edge processing.

Isolation

Tenant isolation in the database

Tenant-scoped tables use Postgres FORCE ROW LEVEL SECURITY, with cross-tenant probes in the test harness. Application authorization is an extra layer, not the only boundary.

Releases

Immutable artifacts, explicit activation

Publishing writes content-addressed release artifacts and activates one through a pointer, which makes rollback deterministic.

Erasure

Crypto-shred erasure with a receipt

Erasure destroys the scoped encryption key, reconciles every declared store and emits a completion receipt only after clean verification.

Access

Audited staff access

Supported staff sessions and back-office actions are written to audited tables and shown in the customer activity feed.

Deployment

Hosted, not self-hosted

Doctorine runs as a hosted service today. Self-hosting is not available yet.

Details, subprocessors and residency are in the Doctorine Trust Center. Trust Center

FAQ

Questions

Does Doctorine need our production credentials?

No. The eval reads public docs and your spec, and tasks run against a sandbox that answers from the spec. Do not send credentials or private production data.

Can we self-host Doctorine?

Not today. If running inside your own network is the blocker, tell us, because it decides what we build next.

How do we report a vulnerability?

Email security@doctorine.xyz with a description, reproduction steps and impact. We acknowledge within 2 business days and make a triage decision within 5.
